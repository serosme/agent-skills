# 编写规范

## 定位

本规范统一技能的写法，但它不是所有 Agent 平台的强制标准。目标平台有明确要求时，先核对其文件位置、元数据和加载方式。

本规范只管技能的结构与内容，不规定标点、空格与排版风格。

## 目录约定

最小可用结构只有一个文件，其余按需增加。

```text
skill-name/
├── SKILL.md
├── references/
├── scripts/
└── assets/
```

- 目录名用小写短横线，例如 `write-skills`。
- `references/` 放详细定义、决策规则和示例。
- `assets/` 放模板和静态素材。
- `scripts/` 放确实要执行的脚本。
- 不创建空目录，也不创建没有文件的附件目录。
- `scripts/` 存在不代表默认允许执行，是否允许执行要单独写明。

## 元数据

```yaml
---
name: skill-name
description: 技能做什么，以及什么情况下使用它。
---
```

- `name` 与目录名一致，小写短横线。
- `description` 一条写清能力与触发场景，不写 `处理所有任务` 这类过宽表述。
- 不加目标平台不要求、也没有明确用途的字段。
- 值含 YAML 特殊字符时加引号。
- 需要用户显式调用、不参与自动匹配时，加 `disable-model-invocation: true`。

## 六个章节

主文件固定使用六个二级章节，不编号。三级小节按任务需要设置，不必求全。

| 章节 | 写什么 | 不写什么 |
| --- | --- | --- |
| 目标 | 要解决的问题与适用模式；需要时补一句不做的边界 | 抽象口号或愿景 |
| 前置条件 | 必要输入、权限或工具、缺失信息怎么处理、执行前读哪些附件 | 没有额外依赖时的安装配置章节 |
| 执行步骤 | 编号步骤，每步写操作，末步是验收 | 每一步重复完整的异常规则 |
| 约束 | 必须遵守的业务规则、禁止操作、需确认操作、默认异常处理 | 穷举所有可能的错误 |
| 输出与验收 | 交付内容与格式、判断正确的标准、部分完成怎么汇报 | 只写命令运行成功 |
| 示例 | 至少一个正常案例，有风险时加一个边界案例 | 把示例当成某条规则的唯一来源 |

补充要求：

- 核心安全边界和停止条件写在主文件，不藏进按需加载的附件。
- 执行步骤写具体动作，避免只写目标、不写做法。
- 验收项针对任务结果，不是命令是否返回 0。
- 示例短就放主文件，长就放 `references/examples.md`，主文件保留引用和读取时机。
- 默认异常处理统一写：能安全修正的先修正，影响正确性的停止并报告。

## 附件引用

- 用相对 `SKILL.md` 的路径引用附件。
- 写明何时必须读、何时按需读，不假设 Agent 会自己遍历目录。
- 文件之间冲突要修正，不靠优先级声明掩盖。
