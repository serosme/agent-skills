# 符号对照

判断某个符号该留还是该删时对照本文。原则只有一条：符号承担信息或节奏才留，只起装饰就删；禁用符号一律替换。

## 案例 1：连用标点表情绪

改前：

```text
这个坑必须避开！！！不然线上一定会挂……
```

改后：

```text
这个坑必须避开，否则线上会挂。
```

判断：感叹号连用和句末省略号都不增加信息，只放大情绪，删掉后语义不变。

## 案例 2：拿 emoji 代替状态文字

改前：

```text
✅ 配置已完成
❌ 监控未接入
```

改后：

```text
配置已完成，监控未接入。
```

判断：emoji 属禁用符号，不因「已经说清」而例外。状态用文字写，不受渲染环境与朗读工具影响。

## 案例 3：中文引号写成弯引号

改前：

```text
他说“这个功能叫‘回滚保护’”。
```

改后：

```text
他说「这个功能叫『回滚保护』」。
```

判断：弯引号属禁用符号，外层换 `「」`，嵌套降一层换 `『』`。若内层是命令或配置项，直接换成行内代码更清楚。

## 案例 4：中文句里混进半角标点

改前：

```text
先跑测试, 再合并(主干), 最后发布.
```

改后：

```text
先跑测试，再合并（主干），最后发布。
```

判断：半角逗号、括号、句号都是禁用符号。半角括号夹在全角文字里字距会突然变窄，扫读时像断了一句。

## 案例 5：括号套括号

改前：

```text
默认配置放在项目根目录（详见附录（二））。
```

改后：

```text
默认配置放在项目根目录，详见附录二。
```

判断：括号用于补充限定，但嵌套两层后句子就散了，拆成短句比换符号更好。

## 案例 6：同类符号混用

改前：

```text
输入 → 校验 -> 入库 => 完成
```

改后：

```text
输入 → 校验 → 入库 → 完成
```

判断：箭头表示数据流向，是有效信息，保留。三种写法混在一行，读者会猜它们是否含义不同，同一篇里只能选一种。

## 案例 7：该用结构的地方还在用符号串

改前：

```text
需要准备账号、申请权限、开通白名单，然后配置环境、跑通流水线、通知测试同学验收。
```

改后：

```text
准备账号、申请权限、开通白名单。

接着配置环境、跑通流水线，通知测试同学验收。
```

判断：顿号没写错，是一句话塞了两组并列加两步动作。断开后读者不用回看前半句，问题不在符号而在符号硬串。

## 案例 8：引号当强调用

改前：

```text
这个“接口”返回“列表”，每个“元素”带“状态”。
```

改后：

```text
这个接口返回列表，每个元素带状态。
```

判断：普通名词不加引号，术语首次出现标注一次就够。到处加引号，读者会以为这些词另有含义或需要逐字对照。

## 案例 9：保留有效的符号

以下是应当保留的写法：

```text
只有一条限制——不能改动线上数据。
他说过「先跑通再优化」，这次按这个来。
```

判断：破折号引出转折后的重点，引号标注原话，都在传递信息，换成文字会更啰唆。删掉后句子仍成立但读起来更平，就不属于滥用。
