# Text Conventions

## 目标

把 Markdown 文件、纯文本文件与代码注释里的中文文本写通顺、读得下去，符号用在该用的地方。少数符号有固定写法，见 **禁用符号**；其余按语义取舍，不滥用。不改内容主张，也不查代码本身、提交信息与对话回复，除非用户明确要求。

## 前置条件

### 必要输入

- 目标文件、目录或明确的改动范围。
- 意图：新写、局部调整还是整篇校对。

### 信息缺失处理

- 无路径时取本次改动的文件，仍不确定则询问。
- 用户未授权改措辞时，只动符号、空格与断句，不动语序与句子结构。
- 涉及二进制、生成产物或第三方目录先确认是否跳过。

### 规则来源

规则见下方 **约束**。拿不准某个符号该留该删时读 [符号对照](references/examples.md)，按需查阅，不必通读。

## 执行步骤

### 步骤 1：确定范围

- 操作：列出文件并确认类型，`.md` 按 Markdown，`.txt` 与无扩展名按纯文本，其余按代码，拿不准先问；已有文件先完整读完。
- 完成标志：文件清单与类型明确，范围与用户意图一致。

### 步骤 2：逐段排查

- 操作：逐段读正文与注释，跳过代码块、行内代码、标识符与字符串字面量。先查禁用符号，再对可疑符号问三句：删掉后意思变不变，能否换成文字或结构，同一处是否承担两种功能；顺带核对中英文空格、Markdown 行首符号与目录树。
- 完成标志：候选改动定位到行，每条写得出理由。

### 步骤 3：改写并验收

- 操作：先替换禁用符号，再删纯装饰符号，需要时换成文字或结构，最后调整共用符号。改后重读受影响段落，复跑步骤 2 查残留，对照验收标准逐条核对。
- 完成标志：改动清单含文件、行号、原文与改后，残留项与待确认项已列出。

## 约束

### 适用范围

- Markdown 文件：正文、标题、列表、表格单元格、引用与中文注释；纯文本文件：全部正文；代码文件：只查中文注释。
- 一律不查：代码块与行内代码内容、URL、代码标识符、字符串字面量。
- 日期、负数、百分比里的 `-` `.` `%` 属数字表达式，不受本规范约束。

### 禁用符号

- 中文引号写 `「」`，嵌套写 `『』`；不用 `“”` `‘’`，也不拿 `"…"` 顶替。
- 不用 emoji，状态与完成度用词句写。
- 中文句子不用半角 `,` `.` `?` `!` `:` `;` 与 `()`，用对应全角标点。
- 不连用标点，如 `！！！`、`？？`；`……` 只写一组。

### 符号使用原则

- 符号只干三件事：断句、结构化、标注原样内容。只起装饰作用就删。
- 不拿符号代替文字：语气、停顿、层级用词句说。
- 同类信息只选一种写法，全篇统一，如同一种箭头、同一种项目符号。
- 嵌套不超过三层，列表套引用再套代码块就到上限。
- 一段话里符号连成串，说明本该用列表或表格。

### 正文标点

- 句末只留一个终止符。
- 引号只用于原话与术语别称，同一术语标注一次就够；术语也可以用加粗，但不并用两种。
- 并列用顿号 `、`，省略号写 `……`，破折号写 `——`，书名与篇名用《》。
- 括号不套括号，需要补充两层时拆句。
- 标点跟随外层句子的语言，引号嵌套降一层，不换另一语言的形制，如：「他把这叫『回滚保护』」。
- 引英文原话时外层仍是中文引号，里面英文照原样，如：日志提示「retry after 3s」；英文句子用英文标点，引中文原话时引号仍用英文形制。
- 命令、路径、标识符、字面量用行内代码包裹，不用引号包。
- 箭头表示流程与指向时写 `→` 或 `->`，同一篇里统一。
- 强调用加粗或改写句式。

### Markdown 行首符号

行首 `#` `-` `1.` `>` 仅用于标题、列表、引用，`|` 与 `---` 仅在表格中成对出现。反引号只作行内代码，`**` 只作加粗，`[]()` 只作链接。分隔线只用于分隔章节，不在一段内容内部代替空行。非 Markdown 文本里 `#` `-` `|` 仅作普通字符，不判违规。

### 排版空格

中文与英文、数字、行内代码、加粗之间各留一个空格，如：使用 Python 3 写代码，用 `print` 输出，这是 **重点** 内容。标点前后不留空格，全角标点与半角空格不混排。英文句子按英文惯例书写。代码注释同样适用。

### 目录树

目录树包在代码块内，语言标记用 `text` 或留空，置于引用块或表格时亦然；纯文本文件不套代码块。连接符只用 `│` `├` `└` `─`，多列对齐可加 `┬` `┼` `┴`，不用 `-` `*`；每级缩进 4 个空格，不限制表符；名称与连接符之间留一个空格，如 `├── src`；多列对齐时列宽按最长名称确定。树内名称按真实路径与标识符原样写，标点只约束说明文字。树外提及结构用行内代码包裹单个路径，如 `src/main.py`。

### 行为边界

- 只改符号、空格、断句与语序；不新增信息、不删观点、不改标题层级。
- 超过一两句的改写或牵涉语气的调整，动笔前说明理由并确认。
- 只处理指定或本次改动的文件，表格结构符号不动。
- 代码块、字符串字面量、标识符与引用原文一律不动，即使含禁用符号；引用里已有 emoji 时按原文保留。
- 删除整段不在范围内，确需删除先征求确认。

### 异常处理

- 改法有多种且会影响语气时保留原文，列为待确认。
- 判断不了该留该删时，按删掉后不损失信息就删处理。
- 用户要求与本规范冲突时指出并请其确认，不静默覆盖。

## 输出与验收

### 交付内容

- 改动清单：文件、行号、原文、改后、理由。
- 保留下来的符号及用途，如箭头表示数据流向故保留。
- 残留项与待确认项。

### 验收标准

以下各项不含按 **行为边界** 豁免的原文片段。

- 没有 `“”` `‘’` 与 emoji，中文句子没有半角标点、半角括号，省略号与破折号写作 `……` 与 `——`，书名与篇名用《》。
- 每个保留的符号都说得清用途，没有纯装饰符号、连续堆叠或符号硬串的长句。
- 引号只用在原话与术语别称上，没有给普通名词加引号；命令与路径用行内代码包裹，没有用引号包。
- 中英文之间空格合规，标点前后无空格。
- Markdown 的行首符号与目录树合规。
- 同类符号全篇风格统一，句末只有一个终止符，结构嵌套不超过三层。
- 改动处语义一致，没有新增或删去信息。
- 只改了范围内的文件，代码内容、字符串字面量、标识符与表格结构符号未动。

## 示例

场景：`docs/guide.md` 与 `src/loader.ts` 需按本规范校对。

- 步骤 1：前者查全部规则，后者只查中文注释。
- 步骤 2：`guide.md` 第 12 行连用叹号、第 20 行拿 emoji 当状态标记、第 30 行用省略号代替停顿、第 44 行箭头混用、第 50 行中文引号写成弯引号；`loader.ts` 第 8 行注释写 `-->` 而全文统一为 `->`。
- 步骤 3：删去重复叹号，把 emoji 换成文字，拆开靠符号硬串的长句，统一箭头，第 50 行改用 `「」`，复跑后报告。

边界案例：`src/loader.ts` 第 14 行注释里嵌着一条可直接执行的命令，形如 `` git commit -m "fix: 修复, 分隔符" ``，含禁用符号。它属于行内代码与原文片段，按 **适用范围** 与 **行为边界** 保留，并列入交付的保留项。

反馈用引用块：

> 改了 6 处：`guide.md` 第 12 行删去重复叹号，第 20 行 emoji 改为「已完成」，第 30 行拆句，第 44 行箭头统一为 `->`，第 50 行改用「回滚保护」；`loader.ts` 第 8 行注释箭头统一为 `->`。
>
> 保留：`guide.md` 第 36 行括号补充默认配置路径，删掉会损失信息；`loader.ts` 第 14 行注释里的命令可原样执行，未改动。
>
> 待确认：`guide.md` 第 52 行引号里是原作者笔名还是笔误。
