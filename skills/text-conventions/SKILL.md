# Text Conventions

## 适用场景

### 目标

把 Markdown 文件、纯文本文件与代码注释里的中文符号统一到一套可判断的规则，覆盖正文标点、行首符号、中英文空格与目录树四类。

### 适用

- 新建或修改 Markdown 文件、纯文本文件。
- 写或改代码里的中文注释。
- 校对指定文件、目录或一批改动。

### 不适用

- 对话回复本身，除非用户明确要求。
- 提交信息，按仓库存量约定书写。
- 代码本身，含标识符、字符串字面量与代码块内容。
- 配置文件的键名、取值与结构不查，中文注释仍受约束。
- 内容改写。本技能只动符号与排版。

## 前置条件

### 必要输入

- 目标文件、目录或明确的改动范围。
- 意图：新写、局部调整还是整篇校对。

### 信息缺失处理

- 无路径时取本次改动的文件，仍不确定则询问。
- 未说能否改措辞时只动符号与空格。
- 涉及二进制、生成产物或第三方目录先确认是否跳过。

### 规则来源

规则在下方 **约束** 一节，无需读取其他文件。

## 执行步骤

### 步骤 1：确定范围

- 操作：列出文件并确认类型，`.md` 按 Markdown，`.txt` 与无扩展名按纯文本，其余按代码，拿不准先问；已有文件先完整读完。
- 完成标志：清单与类型明确，范围与用户意图一致。

### 步骤 2：逐类排查

- 操作：已有文件跳过代码块、行内代码、标识符与字符串字面量，只查正文与注释，按四类规则排查，行首符号只对 Markdown 生效，记录行号与原文；新建文件直接按规则书写，跳过排查。
- 完成标志：适用类别都查过，违规项定位到行。

### 步骤 3：修正并验收

- 操作：按约束改写，改后重读确认语义未变；同句命中多条以不改语义为先；复跑步骤 2 查残留，逐条核对验收标准。
- 完成标志：无残留并报告改动，或已说明阻断原因。

## 约束

### 适用范围

- Markdown 文件：正文、标题、列表、表格单元格、引用、中文注释。
- 纯文本文件：全部正文。
- 代码文件：只查中文注释，代码与字符串字面量不动。
- 对话正文：仅在用户明确要求时按本规范。
- 一律不查：代码块与行内代码内容、URL、代码标识符。
- 日期、负数、百分比里的 `-` `.` `%` 属数字表达式，不受本规范约束。

### 正文标点

只允许 `，` `。` `、` `：` `；` `？`，其余按下列方式改写：

- 成对符号不用 `“”` `‘’` `（）` `[]`。引语用 `：` 引出或用行内代码包裹字面量，术语用加粗，占位符写成 `待填` 样式；圆括号把补充内容拆成短句或前置为定语，方括号改用行内代码或删去。
- 替代符号换掉：`——` 改 `：` 或拆两句，`……` 改 `等` 或删去，`·` 改 `、`。
- 装饰符号删去：emoji 与装饰性分隔线。
- 箭头统一写：写成行内代码 `=>`，不用 `→` 与 `->`。

英文、代码、数学表达式、URL 与 Markdown 语法符号及其包裹内容不受本节约束。

注释里被引号、反引号或行内代码包裹的原文，含命令、参数、路径与报错文本，整体保持原样，不套用本节与排版空格规则。判据是能否原样复制出去直接执行或打开，能则不改。

### Markdown 行首符号

行首 `#` `-` `1.` `>` 仅用于标题、列表、引用，`|` 与 `---` 仅在表格中成对出现。反引号只作行内代码，`**` 只作加粗，`[]()` 只作链接。其余按正文标点处理。

非 Markdown 文本里 `#` `-` `|` 仅作普通字符，不判违规。

### 排版空格

中文与英文、数字、行内代码、加粗之间各留一个空格，如：使用 Python 3 写代码，用 `print` 输出，这是 **重点** 内容。标点前后不留空格，全角标点与半角空格不混排。英文句子按英文惯例书写。代码注释同样适用。

### 目录树

目录树包在代码块内，语言标记用 `text` 或留空，置于引用块或表格时亦然；纯文本文件不套代码块。连接符只用 `│` `├` `└` `─`，多列对齐可加 `┬` `┼` `┴`，不用 `-` `*`；每级缩进 4 个空格，不限制表符；名称与连接符之间留一个空格，如 `├── src`；多列对齐时列宽按最长名称确定。树内名称按真实路径与标识符原样写，标点只约束说明文字。树外提及结构用行内代码包裹单个路径，如 `src/main.py`。

### 行为边界

- 只改符号、空格与目录树连接符，不改措辞、结构、标题层级与内容。
- 只处理指定或本次改动的文件。
- 表格单元格正文同样受约束，表格结构符号不动。
- 代码块、字符串字面量与标识符一律不动，即使含禁用标点。
- 注释里的原文片段按 **正文标点** 的豁免处理，能原样复制执行或打开的不改。
- 删除整段不在范围内，确需删除先征求确认。

### 异常处理

- 改写会改变语义时保留原文，列为待确认。
- 文件过大分段处理，不凭片段下结论。
- 用户要求与本规范冲突时指出并请其确认，不静默覆盖。
- 部分完成时分开报告，不笼统声称全部改好。

## 输出与验收

### 交付内容

- 改动清单：文件、行号、原文、改后。
- 按豁免未改的原文片段。
- 残留项、待确认项与未处理文件的原因。

### 验收标准

以下各项不含按 **正文标点** 豁免的原文片段。

- 正文与注释无白名单外标点，无禁用符号与 emoji。
- 箭头统一写作行内代码 `=>`，没有 `→` 与 `->`。
- 中英文之间空格合规，标点前后无空格。
- Markdown 的行首符号与目录树合规。
- 语义一致，没有增删内容，只改符号与空格。
- 代码块、字符串字面量与标识符未动，注释原文仍可原样复制执行或打开。
- 表格结构符号未动。
- 范围外文件未动。

## 示例

场景：`docs/guide.md` 与 `src/loader.ts` 需按规范校对。

- 步骤 1：前者查四类规则，后者只查中文注释。
- 步骤 2：`guide.md` 第 12 行圆括号、第 20 行缺空格、第 30 行改写会改语气；`loader.ts` 第 8 行注释用箭头。
- 步骤 3：拆句、补空格、箭头改 `=>`，第 30 行待确认，复跑后报告。

反馈用引用块：

> 改了 3 处：`guide.md` 第 12 行拆句，第 20 行补空格；`loader.ts` 第 8 行注释箭头改 `=>`。第 30 行保留待确认。
>
> 按豁免未改：`loader.ts` 第 2 行注释里的 `git commit -m "修复, 问题"` 原样保留。
>
> 代码与字符串未动。
