# Cover

## 目标

编码后的收尾门禁：不碰业务代码，把 `git diff` 涉及的生产代码全部覆盖；每条行为有正向或反向断言；最终本次相关单测全绿、全量无新增失败/跳过/未执行，给出覆盖证据。

- 只补测试：补测期间生产代码零改动（原有功能 diff 保留）；构建脚本与测试配置默认不改，确需加测试依赖时先确认并单列。
- 全量覆盖：本次新增、修改的每一行与每一个分支都至少被一条用例执行；不可达或需改生产代码才能测的列阻断；无覆盖率工具时逐行映射取证。
- 全绿（本次相关）：本次相关测试 0 失败、0 跳过、0 未执行；全量相对基线没有新增失败/跳过/未执行；基线已有项单列并记录决定人。不写红用例，不把疑似 bug 的现状写成期望。
- 单测在进程内自给自足，外部服务一律 fake/mock，不连外部真实库、缓存、消息、网络与第三方接口。

结论只有两个：通过、阻断；没有「带缺口通过」。阻断项记录后继续完成可执行的补测、全量运行与证据收集，最后统一报告；只有输入前提缺失或前置条件不满足（无单测命令、依赖装不上、意图不清、范围不明、没有可测逻辑）才提前停。

## 前置条件

### 必要输入

- 覆盖范围：默认 `git diff HEAD` 与未跟踪的生产文件（`git status --porcelain`）；已提交时给提交区间或分支，也可指定文件或目录。提交区间时终点必须是当前工作树对应的 commit（`git rev-parse HEAD`），不是就先问，避免行号与源码错位。没有改动时先问覆盖什么。历史代码的未覆盖不追。
- 本次相关测试：覆盖本次改动行/分支的测试（新写、改写或已有），以及因本次改动而调整的测试；与本次改动无关的历史测试不算。
- 改动行：diff 中新增（`+`）与修改的行，按新文件行号计；删除行不算，包声明、import 等非可执行行不计。用 `git diff -U0 <范围>` 取行号，未跟踪文件按整文件的可执行行计；排除生成代码或纯样板时在报告单列并说明由哪条用例覆盖。
- 意图来源：`docs/<需求名>/<编号>.md`、接口契约或开发人员口述；要能回答应接受、应拒绝、应保持不变，否则写不出有依据的断言，见 **缺失处理**。口述来源记下原话、人与时间。
- 单测命令：优先取 `AGENTS.md` 命令表，其次构建声明；要明确到单测，混跑时问清单测范围或标签，集成/E2E 不跑。可判定信号按仓库实际取：surefire 只跑单测、failsafe 跑集成、`@Tag`、profile、`-Dtest=` 等；都没有就问。
- 覆盖率命令：同源查找；没有工具也能做，用逐行映射表与分支普查取证。

### 权限与工具

- 读生产代码与测试目录，只写测试文件；测试依赖与配置只在确认后做最小改动。
- 运行单测与覆盖率命令；不启动任何外部服务。
- 不改生产代码；构建脚本与测试配置默认不改。需要测试缝才能测的分支不测并列入阻断，继续完成其余补测与全量运行，最后统一报告。
- 开跑时按覆盖范围解析生产文件清单（diff 与提交区间都适用，含未跟踪文件），逐个记录 `git hash-object --no-filters`，结束时重算比对；测试文件与已确认的测试依赖/配置改动不计入，生产文件有新增改动即阻断。
- 不提交。

### 缺失处理

- 仓库没有测试框架：问是否引入；不引入就停；引入时只加测试依赖与最小配置并单列，不动生产代码。
- 单测命令跑不起来或依赖装不上：报告并停，不换框架、不装全局工具。
- 测试命令必须连数据库、缓存或第三方服务：问离线单测命令或标签；问不到就停，不先起服务再跑，不把集成结果当证据。
- 意图来源拿不到：先问；问不到就停，不能凭现状编期望。
- 改动里没有可测业务逻辑，只有配置、样式或生成代码：说明并停。
- 改动大到一次覆盖不完：按模块拆批，报已完成与未完成，未完成即阻断。
- 某行或分支不改生产代码就无法覆盖（不可达、需要新测试缝）：报告阻断，写清位置与需要什么改动（抽 SQL 构造、可注入仓储边界；仅方言无关的分支可改用进程内嵌入式库），其余继续。

## 执行步骤

### 步骤 1：定范围，列行为与正反断言

- 操作：
  - 从 diff 取新增、修改、删除的生产代码方法，排除测试、配置与生成代码；单元边界按 **单测的边界与期望来源** 划，不按整条业务流程建单测；纯样板（getter、DTO、纯委托）不单独写用例，由上层用例覆盖，覆盖不了列阻断。
  - 对每个方法列场景，标断言类型：
    - 正向：应接受 → 返回值、状态迁移、落库对象与关键值、消息体、事件、缓存变更。
    - 反向：应拒绝 → 异常类型、错误码或兜底值，且状态、库存、余额、消息与副作用不变。
    - 分支：每个 `if`/`else` 两侧、`switch` case 与 default、`catch` 正常与异常、循环 0/1/多、`&&`/`||` 短路、三元两侧、`try`/`finally`、参数空/边界/非法、状态前置与迁移、幂等重复。
  - 每条写「场景 → 期待」，测试名写业务语义。
  - 私有方法通过公开入口覆盖；入口到不了的分支，列阻断并建议提取，不自行改代码。
  - 删除的方法或分支单列，后面清失效用例。
  - 输出改动行清单：用 `git diff -U0` 解析每个改动文件的新文件行号，未跟踪文件按整文件的可执行行计；这份清单是覆盖表、分支普查与计数的共同基准。
  - 输出分支普查表（计划态）：分支/条件 | 应有变体 | 计划覆盖变体 | 阻断 | 计划缺口 | 推导依据。应有变体按类型规则从 diff 独立推导（`if` 2、`switch` case 数 + default、`catch` 2、循环 3、`&&`/`||` 短路组合、`try`/`finally` 2、三元 2、每个边界 2、参数空/非法各 1），写出公式与合计；`switch` 表达式/箭头分支、`instanceof` 模式、循环 `break/continue` 等未列出的源码构造按实际出现计，并在推导依据写清。计划缺口 = 应有变体 - 计划覆盖变体 - 阻断变体（一个用例覆盖多个变体时按变体数计）。
  - 输出外部边界清单：数据库/ORM、缓存、消息/事件、HTTP/RPC、第三方 SDK、时钟、随机数/UUID、文件系统、环境变量；逐个写明单测替换方式，零依赖写「无」。
- 完成标志：每个改动方法都有正反场景与断言类型；改动行清单已给出；每个应有变体都有计划覆盖变体或已列阻断，计划缺口为 0；外部边界有隔离方案或「无」。

### 步骤 2：对齐意图

- 操作：
  - 读或问意图，列应接受、应拒绝、应保持不变的场景与来源（文档文件:行或口述原话）。
  - 与行为清单求差集：意图有、代码没有的；代码有、意图没有的；两边对不上的。
  - 实现与意图不一致、缺守卫/回滚/校验/状态迁移：记录阻断项（位置 + 差异）；不写红用例、不改代码、不按现状迁就；继续完成可执行的补测与全量运行，最后统一报告。
  - 意图本身不清：问；问不清就停，不能继续补测。
  - 可疑行为的判定口径：与意图来源不一致、缺少意图要求的守卫/回滚/校验/状态迁移、吞异常、空值兜底无依据、重复副作用，任一即记录阻断并交开发人员；判断不了先问。
- 完成标志：差集表每条有来源与结论；没有未澄清的意图缺口；不一致与可疑项已按上面的口径列阻断。

### 步骤 3：审计已有用例

- 操作：
  - 跑一次基线：只跑进程内单测，记录通过、失败、跳过、未执行，存成基线集（测试标识 + 状态，如 `类#方法`，参数化按运行标识记）；本次相关的失败/跳过/未执行（含覆盖改动行/分支或失败原因指向本次改动的既有用例）先按步骤 5 的失败分类处理，相关跳过要启用或列阻断，不得计入基线豁免；无关的失败/跳过不改、不跳过，单列并作为后面判断「新增」的对照。
  - 对每条行为找已有用例：有断言、断言在业务结果上、覆盖该分支、期望与意图一致，才算已覆盖；否则补强或重写。
  - 已有用例把「实现允许但业务禁止」的行为固化为期望的，按可疑/阻断处理，不算已覆盖。
  - 补齐正反：只有正向的补反向；反向只断言异常的补状态与副作用不变。
  - 本次行为相关的已有用例若连真实服务，按 **隔离外部服务** 改写成 fake；改不了列阻断；无关用例不动。
  - 删除代码导致的失效用例删除或改写，记录条数。
  - 既有断言只许按意图变强或按依据改，不许静默弱化；变更逐条列原断言、新断言与依据。
- 完成标志：每条行为有「已覆盖/待补」结论；弱用例已补强；断言变更已列出；基线集已记录；没有把连服务用例算成覆盖。

### 步骤 4：补写用例

- 操作：
  - 按 **单测** 与 **正反断言** 写；有既有测试目录与框架就用；没有测试框架而开发人员确认引入时，按构建约定建最小测试目录与命名，和测试依赖/配置改动一起在报告单列。
  - 外部依赖按 **隔离外部服务** 在边界替换：内存 fake 仓储、内存 map 缓存、记录型 MQ fake、进程内 fake 客户端、固定 Clock/随机源/ID。
  - 只 mock 进程内协作者；被测类和领域对象用真实对象，不 mock 它的业务判断或私有方法。
  - 只写测试文件（已确认的测试依赖/配置最小改动除外）；某分支必须改生产代码才能测的，不测并列入阻断，写清需要什么测试缝（抽 SQL 构造、可注入仓储边界；仅方言无关的分支可改用进程内嵌入式库，方言相关分支仍阻断）。
  - 删除失效用例并记录条数。
- 完成标志：每条「待补」都有用例或已列阻断（必须改生产代码才能测的分支）；每个应拒绝分支有反向断言且验证状态不变，或已列阻断；测试文件与用例清单已给出；生产代码零改动。

### 步骤 5：跑全量，补空洞

- 操作：
  - 按单测命令跑全量（不启动服务），记录通过、失败、跳过、未执行；未执行以测试报告的运行条数对照测试文件/用例清单（步骤 4 产出）核对，报告里没出现的用例算未执行；本次相关测试若被 `@Disabled`、排除或没被测试收集，按跳过/未执行处理，不算通过。
  - 结束时按同一口径记录结束集（测试标识 + 状态），与基线集逐项对比：新增失败/跳过/未执行 = 结束集中不在基线集的（测试标识 + 状态）项；基线项在结束集中消失，必须归因为已记录的删除或改写/重命名（含参数化标识变更，且能在测试文件清单、既有断言变更或对比表中对上），否则按「未执行」判新增未执行，归因不明按阻断。
  - 失败/跳过/未执行分类：用例写错或期望错 → 改用例；相关跳过要启用或列阻断；相关未执行要修复收集/运行配置（需确认）或列阻断；实现 bug、与意图不符、环境依赖 → 不写红用例、不改生产代码，列阻断。
  - 覆盖率：以源码级普查为准；有工具时只统计进程内单测，并尽量把报告裁剪到改动行/分支；裁剪不了就给全量数字并说明裁剪方法，不要求工具数字与源码普查相等；编译器合成结构（switch 映射、lambda、try-with-resources 等）不计入源码普查，差异在报告说明。命令要连服务时不跑，按无工具处理。
  - 绿色证据回填（有/无工具都做）：每个改动行给绿色用例或逐行映射；每条改动分支回填到分支普查的「已绿变体 + 绿色用例（用例名 + 文件:行）」；有工具时再附数字与裁剪说明，无工具时逐行映射即主证据；映射对不上代码行或回填不上的算缺口。
  - 补空洞：未覆盖的改动行/分支补用例；补不了（不可达、需改代码）列阻断后继续其余项；不为凑覆盖率造业务上不可能出现的输入。
  - 正反配对自检：逐方法核对「应接受有正向业务值」「应拒绝有反向表现 + 状态不变」。
- 完成标志：本次相关测试 0 失败、0 跳过、0 未执行；全量相对基线 0 新增失败/跳过/未执行（基线已有项单列并有决定人）；源码级改动行与分支 100% 有绿色用例或逐行映射，或对应项已列阻断；分支普查已绿变体 = 应有变体、缺口为 0，或有阻断变体已单列；正反断言齐全或对应项已列阻断；生产文件哈希与开跑快照一致。

### 步骤 6：验收并报告

- 操作：
  - 对照 **验收标准** 逐条核对，未过项按 **判定** 归为阻断。
  - 按 **交付内容** 生成映射表、分支普查、覆盖表与报告，然后停。
- 完成标志：验收项全过或未过项已列阻断；报告与实际一致。

## 约束

### 不改业务代码（生产代码）

- 生产代码零改动：不改实现、不加测试缝、不改可见性、不抽方法、不改依赖注入点。
- 构建脚本与测试配置默认不改；确需加测试依赖时先确认，只做最小改动并单列；不改排除规则或跳过开关。
- 不做「临时改坏再还原」的变异抽查，也不提交。
- 测试失败或覆盖不了，是实现或设计问题：报告阻断，由开发人员改后再跑；不改期待迁就，不按现状写断言。
- 已有断言只许按意图变强或按依据改；变更逐条列原断言、新断言与依据。

### 单测的边界与期望来源

- 目的：锁业务契约、把边界与失败路径变成可重复的本地验证、快速定位回归；不替代集成测试，也不承担运行时过滤，实际过滤非法请求的是生产代码里的校验。
- 边界：单元 = 改动方法的公开入口（或一个类/服务）；仓储、HTTP/RPC 客户端、消息发布、时钟、随机数等进程内协作者用 fake，领域对象用真实；不 mock 被测类本身，不直接测私有方法；纯样板由上层用例覆盖。
- 期望来源：接受、拒绝、边界、状态迁移由业务意图或接口契约定义，不由实现分支反推；实现允许但业务禁止 → 阻断，不写绿测试固化；业务未定义 → 先问，问不到阻断，不按现状写期望。
- 值域与可达性：公开入口可达的输入属于契约，按业务测接受或拒绝；业务明确不可能且入口不可达的值不测，实现里多出的分支记为不可达/多余并列入阻断，不为凑覆盖率造输入。
- 单元与流程：单测只覆盖改动单元自己的判断与进程内可观察副作用；跨单元装配、事务边界、真实 SQL、网络、消息最终一致性归集成/E2E（由开发人员执行，或按 `sequence` 时序图交给 `test` 技能验证），单测证明不了按阻断；一个编排方法内部用 fake 完成全部调用仍算单元，不算跨单元。
- 已有代码：被测对象是已有代码，期望仍来自业务/契约；没有意图来源不能把现状写成期望；特征测试只能锁行为，不能单独作为通过依据。

### 单测

- 一个用例只验证一个行为；同一行为的多个业务字段可一起断言。
- 断言落在业务结果上：返回值、状态迁移、落库对象与关键值、消息体、事件、缓存变更；拒绝路径断言异常/错误码/兜底值 + 状态与副作用不变。
- 不算覆盖：只断言非空、非异常、被调用、调用次数或顺序、无字段级业务值的快照文件、`any()` 宽松匹配、恒真、类型或实例、日志条数；只断言一个字段而放过其他结果。
- 不算覆盖：断言私有字段、内部计数、中间值、日志文本；期望值由实现或同一辅助函数反推。
- 依赖用 fake/mock 隔离；断言 fake 的可观察状态或返回值，不用 `verify` 的参数代替业务结果；不 mock 被测类与它自己的业务判断。
- 用例独立、确定、可单跑；不依赖顺序，不共享可变状态；时间、随机数、UUID 固定。
- 测试名写业务语义；不为复用把用例写成参数化迷宫。

### 正反断言

- 正向：每个应接受场景断言最终业务结果与副作用（金额、状态、条数、余额、库存、消息体、落库字段），不能只看返回值。
- 反向：每个应拒绝场景断言拒绝表现（异常类型、错误码、兜底值），并断言状态、库存、余额、消息与外部副作用不变。
- 边界两侧：边界内用正向断言通过，边界外用反向断言拒绝；参数空、非法各一条反向。
- 异常路径按反向处理：外部超时、抛错、依赖不可用时，断言回滚、补偿或状态不变，不留半成品副作用。
- 幂等：对显式幂等判断的方法，重复提交一条正向（业务完成）+ 一条反向（无重复副作用）；无幂等语义的方法写明不适用，不硬造。
- 只断言抛异常、不看状态，或只断言成功、不看错误副作用，都不合格。
- 期望值从意图推导，不从实现推导；同义反复断言不算。

### 隔离外部服务

- 硬性：用例在进程内自给自足，断网、无 Docker、无数据库服务、无第三方账号也能跑；任何用例需要外部进程、外部端口、外部服务连接串或凭据才能通过，即违例，判阻断；进程内嵌入式库见下文嵌入式库一条。
- 替换到边界：库/ORM → 内存 fake 仓储；缓存 → 内存 map；MQ/事件 → 内存列表或记录型 fake；HTTP/RPC/第三方 SDK → 进程内 fake 客户端（预设响应与异常）；时钟/随机/UUID → 固定值；文件 → 临时目录；环境变量 → 显式参数。
- 进程内嵌入式库（如 H2/SQLite 内存模式）不算外部服务，可用于仓储实现；SQL 方言差异列入报告风险，需要真实数据库方言才能验证的分支仍按阻断。
- 失败路径用 fake 抛异常或返回坏响应构造，不靠真实服务抖动。
- 不用 `@Disabled`、`skipIf`、环境探测、条件短路或排除规则装绿；不把集成/E2E 放进单测目录。
- 全量条数、覆盖率与结论只统计进程内单测；集成测试不属于本技能，不跑、不充抵。

### 覆盖率

- 主指标是源码级可测的改动行与改动分支覆盖，要求 100%（以步骤 1 的改动行清单与分支普查为基准）；不可达、需改生产代码才能测、实现允许但业务禁止或实现多余的分支列阻断；删除的行不需要覆盖，但要清理对应失效用例；全量行/分支只作参考，历史代码不追。
- 覆盖率是找空洞的证据，不是测试目的：100% 只说明没有漏看分支，测试价值在断言业务结果；不可达分支不用假输入凑，报告阻断。
- 有工具：给工具与命令，并尽量把报告裁剪到改动行/分支；裁剪不了就给全量数字 + 裁剪方法说明，不要求工具数字与源码普查一致；编译器合成分支不计入源码普查，差异说明即可。
- 无工具：给逐行覆盖表（改动行 → 绿色用例 `文件:行`）与分支普查（已绿变体 + 绿色用例）；缺任一行或分支即阻断，不写「无工具所以通过」。
- 覆盖率命令要求连服务：不跑，按无工具处理，不为了数字启动服务。
- 不为覆盖率写无断言用例、加忽略标记、跳过用例，或改实现形状迁就测试。

### 异常

- 全量里出现失败、跳过、未执行：与基线集按（测试标识 + 状态）对比分类；新增失败/跳过/未执行项判阻断；与本次改动无关的基线已有项单列并证明（测试标识、基线状态、结束状态、决定人），不修、不跳过，不阻断；基线项若覆盖本次改动行/分支或失败原因指向本次改动，属于本次相关，按 **步骤 5** 分类处理，不得按基线豁免；决定人拿不到按阻断处理。
- 外部服务不可用导致失败：不是环境免责，按 **隔离外部服务** 改 fake 或列阻断。
- 测试命令跑不起来、依赖缺失、意图缺失、范围不清：报告并停，不猜、不换框架。
- 中途叫停：报已覆盖方法、已写用例、未覆盖项与当前判定（阻断）。

## 输出与验收

### 判定

- 通过：同时满足以下全部。
  - 本次改动的每一行与每一个分支都有至少一条绿色用例；分支普查已绿变体 = 应有变体，缺口为 0。
  - 每个改动方法有正向断言；有拒绝/守卫/边界的分支有反向断言，且验证状态与副作用不变。
  - 本次相关测试 0 失败、0 跳过、0 未执行；全量相对基线 0 新增失败/跳过/未执行；与本次无关的基线项已单列并记录决定人，覆盖改动行/分支或原因指向本次改动的基线项已按本次相关处理。
  - 补测期间生产代码零新增改动：结束时生产文件哈希与开跑快照一致；测试依赖/配置如有经确认的最小改动，单独列出。
  - 映射表、分支普查、覆盖表引用同一份改动行清单，计数一致；没有「待补」。
  - 覆盖率证据齐全：源码级改动行/分支 100%；有工具时给数字并说明是否裁剪到 diff，并按交付要求附逐行/逐变体回填；无工具时逐行映射与分支普查齐全。
  - 外部边界全部隔离；没有连服务用例；没有本次新增的跳过、排除规则或本次相关测试的未执行；与本次无关的基线跳过/失败按 **异常** 单列，不算违反本项。
  - 意图差集已闭合；没有未澄清缺口、疑似实现 bug、可疑行为或其它阻断项；已记录的阻断项全部修复并重跑清零。
- 阻断：任一不满足即阻断，逐条列出；不改代码、不降断言、不上红用例、不写「带缺口通过」。
- 只有这两种结论。

### 交付内容

- 第一行：结论与计数（改动方法、改动行、改动分支、行为、正/反向断言数、本次相关测试通过/失败/跳过/未执行、本次新增用例、全量用例、全量失败/跳过/未执行、新增失败/跳过/未执行、阻断项）；用例数按测试运行条数计，参数化一次运行算一条，基线/新增/删除同口径。
- 行为 → 断言映射表：行为（场景 → 期待）| 类型（正/反）| 用例名 | 断言点（业务结果）| 测试文件:行 | 期望值 | 期望来源（文档:行/口述：人 + 日期）| 状态。
- 分支普查表（绿色态）：分支/条件 | 应有变体 | 已绿变体 | 阻断 | 缺口 | 绿色用例（用例名 + 文件:行）| 推导依据；缺口 = 应有变体 - 已绿变体 - 阻断变体；附 diff 构造清单与变体公式。
- 改动行覆盖表：有工具给数字、裁剪说明与工具合成分支差异，并附逐行/逐变体绿色回填（同无工具表）；无工具逐行给 `文件:行` → 绿色用例 `文件:行`。
- 外部依赖隔离清单：外部边界 | 触达方法 | 隔离手段 | 用例；注明被测类与领域对象为真实对象，替身只在进程内协作者边界。
- 测试命令与结果：通过、失败、跳过、未执行；本次相关测试清单（标识 + 结果）；全量条数 = 基线条数 + 新增 - 删除，并与对比表勾稽；附基线集 vs 结束集对比表（测试标识 | 基线状态 | 结束状态 | 新增/基线/删除/消失/改写 | 决定人），删除、消失或改写项必须有归因。
- 测试文件清单：新增/修改的测试文件路径与条数。
- 生产代码改动：补测期间无；附开跑与结束时的生产文件清单、各文件哈希与 `git diff --stat`，证明生产文件未变（原有功能改动本身保留）。
- 测试依赖/配置改动：无，或列文件、改动内容、确认人；不计入生产文件快照。
- 既有断言变更：原断言、新断言、依据；无则写「无」。
- 意图差集与阻断项：每条有位置、现象、为什么阻断、需要什么改动/测试缝、后续由谁验证（开发改设计，或转集成/E2E 由开发人员或 `test` 技能验证）。
- 确认记录：需要开发人员决定的实现问题、意图缺口、无法隔离的分支、无关基线失败/跳过的处理决定，记人与时间；拿不到决定人按阻断处理。
- 工作区状态：未提交、未做「临时改坏再还原」；说明 HEAD 与 `git status`。
- 部分完成：中途停止时列已覆盖方法、已写用例、未覆盖项与当前判定（阻断）。
- 环境声明：未启动外部服务、未配外部服务连接串、未监听端口；使用进程内嵌入式库（H2/SQLite 内存模式）时单独注明。
- 报告在会话里给出（开发人员指定位置时才落盘），在最后一次编辑与全量运行之后生成。

### 验收标准

- 结论是「通过」或「阻断」，与判定一致；通过时阻断项为 0；没有带缺口通过、红用例、未测白名单。
- 每个改动方法都有用例；每个改动行与分支都在映射/普查里有绿色用例，分支普查已绿变体 = 应有变体，行为映射表每行有期望来源，计数对得上。
- 每个应接受场景有正向断言；每个应拒绝、边界、异常场景有反向断言且验证状态与副作用不变；有显式幂等判断的方法有一正一反，无幂等语义的写明不适用。
- 本次相关测试 0 失败、0 跳过、0 未执行；全量相对基线 0 新增失败/跳过/未执行；与本次无关的基线项已单列并有决定人；覆盖本次改动行/分支或失败原因指向本次改动的基线项已按本次相关处理，未按基线豁免。
- 本次相关测试清单已给出；基线对比表含新增/删除/消失/改写/重命名项与归因，全量条数勾稽一致。
- 补测期间生产文件哈希与开跑快照一致；测试文件之外没有未列出的改动；测试依赖/配置若有经确认的最小改动，已单列。
- 覆盖率证据齐全：源码级改动行/分支 100%；有工具时给了数字、命令、裁剪说明与逐行/逐变体回填（或全量数字 + 裁剪方法），无工具时逐行映射与分支普查齐全；工具合成分支与源码普查的差异已说明。
- 断言都在业务结果上；没有弱断言、实现细节断言、同义反复；一用例一行为、可独立单跑、无顺序/共享状态依赖、时间/随机/UUID 固定、不用 `verify` 参数代替业务结果、测试名写业务语义；没有 mock 被测类本身或领域对象，替身只用于进程内协作者。
- 期望值来自意图/契约，不是按实现分支反推；实现允许但业务禁止的行为没有被写成绿测试；业务未定义的分支已问清或列阻断。
- 单元边界是改动方法的公开入口；跨单元装配、真实 SQL/事务/网络没有被包装成单测，单测覆盖不了的已列阻断。
- 外部服务全部 fake/mock；没有连外部真实库、缓存、消息、网络、第三方接口的用例；进程内嵌入式库按 **隔离外部服务** 的约定使用并注明。
- 意图差集闭合；疑似 bug 与可疑行为已修复后重跑清零，或不存在；不存在「已列阻断」但结论通过。
- 阻断项每条有位置、现象、原因、需要什么改动/测试缝与后续验证人。
- 交付包含测试文件清单与本次相关测试清单；既有断言若变更，逐条列了原断言、新断言与依据。
- 未提交、未做「临时改坏再还原」；报告、行号、计数与实际一致。

## 示例

输入：`OrderService.pay` 新增支付、重复支付拒绝、余额不足拒绝、金额 0 拒绝、金额等于余额通过、超时回滚。范围文档要求超时回滚恢复库存。

行为与断言：

- 正向：支付成功 → 订单 PAID、余额 900、库存扣减 1；金额等于余额 → 通过。
- 反向：重复支付 → 拒绝、订单与余额不变；余额不足 → 拒绝、状态不变；金额 0、空、非法 → 拒绝、状态不变；超时 → 回滚、库存恢复 10（fake 可观察的补偿逻辑，非数据库事务）。
- 期望来源：支付、拒绝、边界规则来自接口契约与范围文档（超时回滚恢复库存），不按实现分支反推；文档未定义的上限值不造用例；实现若真有该分支，先问或列阻断。
- 分支普查：3 个 `if` × 2 + 1 个 `catch` × 2 + 1 个边界 × 2 + 参数空/非法 2 = 12，已绿 12，0 缺口；diff 构造清单：`pay:10` 边界比较、`pay:12` if 重复支付、`pay:15` if 余额不足、`pay:18` if 金额 0、`pay:22` catch 超时，共 5 个构造。
- 隔离：单元是 `pay`，仓储、账户、库存、时钟是 fake 边界；未启动数据库、容器与 mock server；真实 SQL/事务不在单测范围。

用例（示例）：`pay_success` 断言 `PAID`、余额 900、库存 9；`pay_amount_equals_balance` 断言余额 0、订单 PAID；`pay_duplicate_rejected`、`pay_insufficient_rejected`、`pay_amount_zero_rejected`、`pay_amount_empty_rejected`、`pay_amount_negative_rejected` 各自断言错误码且订单、余额、库存不变；`pay_timeout_restores_inventory` 用 fake 抛超时，断言订单回滚、库存 10。8 条全部绿色，覆盖 12 个变体。

绿色态普查（节选）：`pay:12` 重复 if 两侧 → `pay_success` / `pay_duplicate_rejected`；`pay:15` 余额不足两侧 → `pay_success` / `pay_insufficient_rejected`；`pay:18` 金额 0 两侧 → `pay_success` / `pay_amount_zero_rejected`；`pay:22` catch 两侧 → `pay_success` / `pay_timeout_restores_inventory`；`pay:10` 边界比较 → `pay_amount_equals_balance` / `pay_insufficient_rejected`；参数空 → `pay_amount_empty_rejected`，非法 → `pay_amount_negative_rejected`。

意图差集：范围文档要求超时回滚恢复库存，实现一致，差集为空。

覆盖率：`mvn -q test jacoco:report`，按 `git diff -U0` 取改动行；源码级改动行 100%、改动分支 100%（3 个 `if`、1 个 `catch`、1 个边界）；工具合成分支与普查差异 0。

跑全量：基线 7 条（6 通过、1 条历史 `@Disabled` `LegacyOrderTest#legacyPay`）；新增 8 条全绿；全量 15 条中 14 通过、0 失败、1 跳过（基线已有）、0 未执行；相对基线新增失败/跳过/未执行 0；历史跳过单列，决定人张三 2026-11-20 确认与本改动无关；补测前后生产文件哈希一致；测试文件新增 `OrderServiceTest.java` 8 条；未提交、未做变异抽查。

报告：判定通过；改动方法 1 个、改动行 14 行、改动分支 5 个（变体 12 个）、行为 8 条、正/反断言 2/6、本次相关测试 8 通过/0 失败/0 跳过/0 未执行、新增用例 8 条、全量 15 条、通过 14、失败 0、跳过 1（基线）、未执行 0、新增失败/跳过/未执行 0、阻断项 0；分支普查 12/12；测试依赖/配置改动无，既有断言变更无；覆盖证据、测试文件、生产文件哈希与工作区状态均已列出。
