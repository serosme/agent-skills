# Test

## 目标

输入固定为 `sequence` 产出的一张时序图；按图在当前工作区的代码与正在运行的服务上跑一遍，每步核对业务结果、业务不变量与库端实测；最后只在会话里报告这条流程过不过、哪一步没过、为什么。

- 这是技能链中的验证环：上游是 `sequence`，环境来自 `init` 盘点的 `AGENTS.md`；不接口述流程，也不自己编流程。
- 时序图默认已有对应实现；图上的 commit 可以还没填（开发中），本技能只跑当前代码与当前服务，不要求图上的 commit 已填。
- 接口通道为主，页面通道只做冒烟；不写测试记录文件，报告只在会话里给出。
- 业务不变量与库端实测是 AND：有落库副作用的步骤，接口返回成功不能代替库里查到的结果。

只测图上的业务主干与业务级分支。图上画出的 alt、前提与拒绝负例、状态副作用都在流程内；方法内部的参数校验失败、状态机非法迁移、单接口 500 归 `cover` 的单元测试（这里指单元测试层面的异常分支；流程主干实际出现的 5xx 不归 cover，按步骤 5 分类）；并发、幂等重放、消息最终一致性、性能是正交专项，图外才需要开发人员点名。

所有图跑完 = 图覆盖的正向流程不退化，不等于覆盖所有情况；图本身画错测不出来，靠人守图。未经开发人员确认，不得仅凭图或契约不符判实现失败。

## 前置条件

### 必要输入

- 一张 `sequence` 时序图文件；只接受时序图，不接受口述流程。没有时序、只有入口表与结果行的 `sequence` 文件也算合法输入。
- 功能点编号与名称；图里有就用图里的，没有就用 `01`。
- 环境：工作区根目录 `AGENTS.md` 的服务表与基础设施表，取接口基地址、页面地址（页面方式）、库名与主机/端口；数据库连接名由开发人员给，具体连接与查询按 `dbx` 技能。`AGENTS.md` 缺失、关键项为空或可能过期时，先问开发人员。
- 凭据：能登录的测试账号，或现成的 token；两者都比对时准备两套账号或隔离数据，无法隔离时页面轮标 `未执行`。

### 工具技能

- 数据库访问按 `dbx` 技能：连接、schema、只读查询都由它执行，具体命令与参数按该技能。
- 页面流程按 `agent-browser` 技能：打开页面、执行操作、读取页面结果都由它执行。
- 接口流程直接调接口，不绑定具体 HTTP 客户端。

### 通道选择

- 默认接口流程，不碰浏览器。
- 开发人员明确要求页面流程时按 `agent-browser` 技能；要求两者都比对时先接口后页面，分别报告，不写文件。
- 两轮要使用不同账号或隔离数据；无法隔离时页面轮标 `未执行` 并写明原因，不把状态冲突写成业务退化。接口轮已经判业务退化的步骤，页面轮依赖它的步骤记 `未执行`。
- 页面流程只做冒烟：关键元素出现、关键数据落库、页面展示与库一致；深断言交给接口通道。页面步骤没有库端对象时写 `不适用：原因`，关键元素与页面结果仍要写。
- 功能点没有用户端，例如定时任务、回调、清理任务，接口流程直接调触发接口或按触发条件等；报告首行写 `（接口流程，无用户端）`。

### 环境来源与过期

- 环境信息优先从 `AGENTS.md` 取；缺失或过期时用开发人员确认的口述值；不重新扫描仓库生成环境信息，不启动、不重启、不停止服务。
- 按 `init` 的过期规则核对：扫描超过 7 天，或任一仓库 HEAD 与 `AGENTS.md` 记录不一致，标「可能过期」。可能过期时做只读实测（读配置、环境变量、`git rev-parse`、端口连通性），在步骤 3 向开发人员说明差异，并提示重新运行 `init` 刷新 `AGENTS.md`，不把过期值当结论。
- 只在非生产环境跑；不碰无关服务、端口、配置与部署脚本；服务没起来就报告，不自行启动。

### 缺失处理

- 没有时序图：先要一张 `sequence` 时序图，不拿口述流程凑数。
- 基地址、库名、账号、数据库连接名任一缺失，或 `AGENTS.md` 标为未确认/可能过期时，先问；不猜，不拿生产库凑合。
- 环境连不上或服务没起来时报告并停，不自行换环境、换端口，不自行启动服务。
- 图上的入口读不到、当前代码找不到对应实现时，先确认图与代码是否同一版；确认不了就停，不按图硬编。
- 流程里需要短信验证码、支付回调、人工审核这类外部环节时，停下来向开发人员要输入，不伪造。

## 执行步骤

### 步骤 1：读图出清单

- 操作：
  - 读入口表、时序、前提与拒绝、状态副作用；按图从上到下逐步列：这一步做什么 → 怎么执行（请求方法与路径，或页面动作）→ 核对项（业务不变量与库端该看到什么）→ 实际结果记在哪。
  - 有状态副作用表的逐行落到对应步骤；有前提与拒绝表的，身份与初始状态作前置，必须被拒的动作各列一行负例；负例用独立会话或新手机号。
  - 图上的 alt 各列一行，默认也用独立会话或新手机号；图语义要求沿用前序状态的 alt（如 60 秒内重复请求）在步骤 3 说明沿用依据，不默认共用可能被前序污染的状态；带触发条件的 Note 也列一行，标明靠等还是靠调接口验证。
  - 图上有 `stale@` 行时先说明，问开发人员这张图是否仍可作为本次依据；不能就停。
  - 没有时序、只有入口表与结果行的文件：按入口表顺序执行，结果行作为核对项，不自行编顺序。
  - 图外不加行：边界、异常、并发、性能要测，得由开发人员点名并标 `（额外）`；方法内部的分支不在本技能加。
  - 图上没写清业务期待或不变量时，问开发人员补一句，写进清单，不自己编。
- 完成标志：清单每行都能在图上、入口表与结果行上对上；图外没有加行；每行都有核对项，负例也列了。

### 步骤 2：核对环境与连接

- 操作：
  - 先按地址、库名与开发人员的说明判断是否非生产；判断不了或指向生产就先问，不先探活、不先连库。
  - 非生产判断后再做只读检查：确认接口基地址可达；页面方式再确认页面能打开。
  - 按 `dbx` 技能确认连接可用、连的是要测的库；连接名与库名由开发人员确认。
  - 核对 `AGENTS.md` 的扫描时间与各仓库 HEAD；可能过期就按 **环境来源与过期** 做只读实测，留到步骤 3 说明。
- 完成标志：非生产判断已记录，接口（页面方式再加页面地址）可达，连接与库已核对；业务请求与页面操作还没开始。

### 步骤 3：确认环境与测试流程

- 操作：
  - 先把环境信息报给开发人员：`AGENTS.md` 的来源与扫描时间、各仓库 HEAD、接口基地址、页面地址（页面方式）、库名与主机/端口、数据库连接名、非生产判定、可能过期项与只读实测差异；请确认或纠正。
  - 再把大致测试流程报过去：被测功能点与依据图、方式（接口、页面、两者都比）、步骤数与每步一句话（含负例与 alt）、断言深度（接口深、页面冒烟）、哪几步需要他给输入、负例与 alt 是独立会话/新手机号还是沿用前序状态（沿用要说明依据）、图外不做的部分；两者都比对时报隔离方式。
  - 等他回话。改了环境信息或流程就更新并再报一次；改了地址或方式就重查一遍环境。
  - 确认前不执行。
- 完成标志：开发人员已明确确认环境信息与大致测试流程。

### 步骤 4：按清单执行并逐步记录

- 操作：
  - 接口流程直接调接口，一次一个请求；登录态、变量与 cookie 在同一个执行上下文里保持，用完不落盘；不碰浏览器。
  - 页面流程按 `agent-browser` 技能打开页面、照着用户那一步操作、读页面上看到的结果；不直接调接口绕页面，登录或前置需要接口时先经开发人员确认。
  - 每步记下实际发出的请求或页面动作、状态码与关键返回，或者页面上看到的结果。
  - 执行完立刻核对：有落库副作用的步骤，业务不变量与库端实测都要有实测值（查询对象、定位键、结果值，例如 `会话表 count=1，手机号 138****`）；没有库端对象的步骤写 `不适用：原因`，不适用要经开发人员确认。
  - 库端按 `dbx` 技能做只读查询；定位用刚产生的标识，例如手机号、单号、时间窗。负例要核对「被拒且无副作用」，只断言 400/401 不算过。
  - 页面通道只写关键元素、关键数据与页面/库一致性，不展开深业务不变量。
  - 每步的结果留在会话里的清单中，不写测试记录文件。
  - 执行中要加行或改范围，按步骤 3 更新计划并再确认，标 `（额外）`；缺前置数据就问开发人员要，不造数据。
- 完成标志：已跑的行都有核对项、实测值或经确认的 `不适用`、实际结果；未跑的行也已标明，或按步骤 5 处理。

### 步骤 5：失败与偏差分类

- 操作：
  - 与期待不一致时停在这一步，把实际返回、页面结果与库端现状记下来，按下面顺序判断：
    1. **环境问题**：连接不可用、查询被拒、连错库、凭据或外部输入不可用。该行记 `未执行`；整份结论按判定汇总；附报错原文。
    2. **图过期或契约破坏**：先看代码与图的入口、顺序、分支、副作用是否还对得上。有对外契约文档或其他消费方、且实现改坏了契约 → 契约破坏（开发人员确认是实现问题才计未通过）；主干返回 5xx → 业务退化，计未通过；返回与图不符且开发人员确认是实现问题、但没有契约依据 → 契约破坏或业务退化，计未通过；只有图与代码不符且未确认为实现问题，才是图过期。图过期按 `sequence` 约定只在时序图回写一行 `stale@<日期> <原因>`，不改入口/时序；该行记 `未执行`；整份按判定汇总；未经开发人员确认，不得仅凭图或契约不符判实现失败。
    3. **业务退化**：接口按图走通，但业务不变量或库端副作用不对。该行记 `未通过`；整份按判定汇总。
  - 流程自己产生的记录在库里查不到，先确认同一个库、同一时间窗、同一标识；确认是本次流程产生的，按业务退化记，不归环境问题。
  - `查不到` 与 `无法核对` 先记 `待确认`，确认后回填四类之一：自己流程的记录查不到按业务退化；连接/查询被拒按环境问题；该行结论不得为 `通过`。
  - 开发人员不确认性质时记 `待确认`，整份按判定汇总（不得为 `通过`，已出现的 `未通过` 不降级），在报告里列为未确认项；确认后回填四类之一。
  - 判断不了就问开发人员，不自己改数据、改配置、改代码去让它过；开发人员要求继续时跳过该步，记 `未执行` 并写原因，不算通过。
- 完成标志：每个失败或偏差都有实际证据与类别（含 `待确认`），且已由开发人员确认性质或标为待确认。

### 步骤 6：验收并报告

- 操作：
  - 按 **判定** 给整份结论：任一行 `未通过` → 未通过；否则有 `未执行`/环境问题/图过期/非实现契约破坏/待确认 → 未跑通；全部行通过 → 通过。
  - 对照 **验收标准** 逐条核对，修正后重查；两者都比对时两份报告都核，合并结论按「未通过 > 未跑通 > 通过」。
  - 在会话里按 **报告格式** 报告结论、失败步骤、偏差类别与未覆盖项，然后停。
  - 不写测试记录文件。
- 完成标志：结论与判定一致；报告已给出；阻断或部分完成时按判定交付（不把没跑完写成通过，也不把已出现的 `未通过` 降级）。

## 约束

### 测试范围

- 只跑这一张时序图的这一条流程；图上画出的 alt、前提与拒绝负例、状态副作用都算流程内，逐个走，不标 `（额外）`。
- 方法内部参数校验失败、状态机非法迁移、单接口 500 不在本技能；它们归 `cover` 的单元测试。这里指单元测试层面的异常分支；流程主干实际出现的 5xx 或返回与图不符，按步骤 5 分类，不推给 cover。
- 图外的边界、异常、并发、幂等重放、消息最终一致性、性能不在本技能；开发人员点名的才加行，并在步骤名后标 `（额外）`。
- 开跑前要有开发人员对环境和流程的明确确认；执行中加步骤或改范围，更新计划并再确认。没确认不执行。
- 只验证，不顺手修 bug：发现实现问题只记录，改不改、谁来改由开发人员定。
- 不写测试用例集，不引测试框架，不改项目里的测试目录，不改图的入口/时序内容；不写测试记录文件；图过期只按 `sequence` 约定回写 `stale@` 一行。

### 环境与数据

- 只在非生产环境跑；开跑前先判非生产，任一项指向生产就停。
- 环境信息优先从 `AGENTS.md` 取；缺失或过期时用开发人员确认的口述值；不启动、不重启、不停止服务，不自行扫描刷新 `AGENTS.md`；可能过期时按只读实测核对，在步骤 3 说明差异并提示重新运行 `init`。
- 不碰无关服务、端口、配置与部署脚本。
- 流程自己产生的数据默认保留，不删、不重置；要清理由开发人员自己做或明确批准。
- 不造前置数据绕过条件，例如直接插入用户或会话；缺前置数据就问开发人员要。

### 断言

- 有落库副作用的步骤，业务不变量与库端实测都要有实测值；接口返回 token、200 或「行存在」不能代替库端结果。
- 「新增一条」要给条数或关键字段值，例如 `count=1`、`expire_at=…`；「状态已变」要给旧值与新值。
- 负例要核对「被拒且无副作用」；只断言 4xx/401/状态码不算过。
- 页面通道只做冒烟：关键元素、关键数据落库、页面与库一致；没有库端对象的步骤写 `不适用：原因`。
- 没有可观察业务结果的步骤，`不适用` 要经开发人员确认并写原因；断言只写业务可观察结果，不写方法内部实现细节。
- 业务不变量对不上时按业务退化记录，不拿「接口返回成功」当通过。

### 报告

- 只在会话里报告，不写测试记录文件；报告只有结论、方式、结果计数、关键核对或失败/未跑步骤、偏差类别与未覆盖项，不写环境、commit、基线、文件名等元数据。
- 通过时给结论、步数与关键核对，不逐步列全表；未通过时列失败步骤与证据。
- 报告里不写密码、完整 token 与手机号中间位；用 `<token>` 占位。
- 记录只覆盖这一张图；所有图跑完只说明图覆盖的正向流程不退化，不说明覆盖所有情况。

### 执行方式

- 接口流程不变更请求路径、方法或参数去适配报错；改成能过的不算测试。
- 页面流程只操作这条流程涉及的页面，不点无关入口，不改账号设置，不做批量或删除类操作。
- 需要多步串联时可以在临时目录放一次性脚本，用完说明它不留在仓库里；不在仓库里新建测试脚本目录。
- 数据库只用 `dbx` 技能的只读查询，具体权限与命令按该技能；被拒绝时报告，不换客户端绕过。

### 异常

- 网络超时、连接中断时重试一次；仍失败就记录并停在该步，不换环境。
- `dbx` 技能连不上或查询被拒时，按 `dbx` 技能的错误处理；仍不可用就记环境问题，该行 `未执行`；整份按判定汇总（不得为 `通过`，已出现的 `未通过` 不降级），不拿别的客户端直连库。
- 外部输入等不到时把该步标 `未执行`，继续问清再决定是否停下。
- 开发人员不确认偏差性质时记 `待确认`，整份按判定汇总（不得为 `通过`，已出现的 `未通过` 不降级），不猜。
- 中途叫停时保留会话里已跑的结果，下次从步骤 1 重新核对清单，再按步骤 3 确认一次环境与流程才开跑。
- 阻断或部分完成时，报告照写，结论按判定汇总（不把没跑完写成通过，也不把已出现的 `未通过` 降级）。

## 输出与验收

### 判定

- 整份结论只有三个：通过、未通过、未跑通。
- 任一行 `未通过`（业务退化，或确认是实现问题的契约破坏）→ 未通过。
- 否则有 `未执行`（环境问题、图过期、非实现契约破坏、待确认、外部输入等）→ 未跑通。
- 图上入口表与主干的每一步，以及 alt、负例、Note、状态副作用，只进未覆盖、没有对应行时，不得记 `通过`，至少记 `未跑通`。
- 全部行 `通过` → 通过。
- 双通道合并：未通过 > 未跑通 > 通过。阻断或部分完成时按判定汇总：只禁止写成 `通过`，不降级已出现的 `未通过`。

### 报告格式

通过：

````text
<编号> <功能点名>（接口流程 / 页面流程，冒烟 / 接口流程，无用户端）：通过
结果：通过 N / 未通过 0 / 未执行 0
关键核对：<1 到 4 条业务不变量与实测值；有负例/Note 时各给一条>
````

未通过：

````text
<编号> <功能点名>（方式）：未通过（一句原因）
结果：通过 N / 未通过 N / 未执行 N
- 第 N 步 <步骤>：核对项 <...>；实际 <...>；偏差类别 <图过期/契约破坏/业务退化/环境问题/待确认>
偏差：<...>
未覆盖：<...>
````

未跑通：

````text
<编号> <功能点名>（方式）：未跑通（一句原因）
结果：通过 N / 未通过 0 / 未执行 N
已跑：<通过的步骤>；未跑/阻塞：<步骤与原因>
偏差或阻塞：<...>
未覆盖：<...>
````

报告不列环境、commit、基线；双通道时两份报告分别标方式，合并结论按优先级。

### 交付内容

- 会话里的报告；不写测试记录文件；两份报告分别标方式。
- 通过、未通过、未执行的条数；偏差清单与类别；`待确认` 单独列出。
- 两者都比对时报两份报告的合并结论。
- 未跑通或部分完成时按未跑通模板报已跑、未跑步骤、原因与未覆盖。

### 验收标准

- 报告在会话里给出，没有生成测试记录文件；结论只用通过/未通过/未跑通，行结论只用通过/未通过/未执行。
- 报告首行标了方式（接口 / 页面冒烟 / 无用户端），两份报告分别标方式，并有结果计数（通过时通过数等于清单行数；状态副作用并入对应步骤行、不另计；`（额外）` 行不计入）；通过时关键核对 1 到 4 条（有负例/Note 时各给一条）；未通过时列失败步骤、核对项、实际结果与偏差类别；未跑通时列已跑/未跑与原因；报告没有环境、commit、基线等元数据。
- 图上入口表与主干的每一步，以及 alt、前提与拒绝负例、带触发条件的 Note、状态副作用，都必须有对应行；未跑的行记 `未执行` 并同时进未覆盖，不能只进未覆盖。
- 每行都有核对项、实测值或经确认的 `不适用`、实际结果；图上有状态副作用（含页面通道有库端对象）的步骤只能给库端实测值，不得写 `不适用`；`不适用` 仅限图上无库端对象的步骤，且在步骤 4 经开发人员确认并写明原因（通过报告可附在该步关键核对后，不占 1 到 4 条；未通过/未跑通报告写在该步或未覆盖里）；未执行行写 `未执行` 与原因，不要求实测值；有落库副作用的步骤没有只写接口返回；「新增一条」给条数或关键字段，「状态已变」给旧值与新值；负例与 alt 在独立会话或新手机号下执行，或在步骤 3 已说明沿用依据；负例有「无副作用」的实测值。
- 页面通道有关键元素、关键数据与页面/库一致性；没有库端对象的步骤写了 `不适用：原因`，没有展开深业务不变量。
- 偏差每条都带五类之一；图过期没有记成实现失败；环境问题没有被写成业务退化；业务退化/实现问题也没有被写成图过期或环境问题；`待确认` 已单列。
- 请求的方法、路径与参数按清单发出，没有为了绕过报错改过；页面流程没有直接调接口绕页面。
- 没有图外新增的边界、异常、并发、性能测试；开发人员点名加的行已标 `（额外）`；图上的负例与 alt 没有误标。
- 没有写数据库、没有启动或重启服务、没有改配置、代码与项目里的测试目录，没有装依赖；环境过期时只做只读实测。
- 断言只写业务可观察结果，没有方法内部实现细节；页面流程没有点无关入口、改账号设置或做批量/删除类操作。
- 报告里没有密码、完整 token 与手机号中间位。
- 失败步骤停在原处如实记录，没有被改数据或跳过后算成通过，流程产生的数据也没有被删或重置。
- 临时脚本与日志已清理，或已说明不留在仓库。
- 开跑前环境信息与大致流程已由开发人员确认；中途加点已再确认并标 `（额外）`。
- 报告没有把本次流程说成覆盖全部情况。

## 示例

功能点「01 短信验证码登录」，时序图来源现状。`AGENTS.md` 服务表给出基地址 `http://localhost:8080`，基础设施表给出 `chat@localhost:3306`，数据库连接名由开发人员给。开发人员确认环境与流程后开跑。

清单六行：取图形验证码、请求下发短信、重复请求 alt、未先取图形验证码提交登录（负例）、提交登录、验证码 60 秒未使用自行作废（Note）。负例用独立会话；重复请求 alt 与 60 秒作废 Note 依赖同一手机号的冷却状态，沿用同一手机号，已在步骤 3 向开发人员说明沿用依据。

未通过时的报告：

````text
01 短信验证码登录（接口流程）：未通过（业务退化）
结果：通过 4 / 未通过 1 / 未执行 1
- 第 5 步 提交登录：核对项「会话新增一条，用户进入登录态」；实际「200+token，会话表 count=0，用户没进入登录态」；偏差类别 业务退化
偏差：第 5 步业务退化，开发人员张三确认实现问题，未修。
未覆盖：第 6 步验证码 60 秒作废，因第 5 步已停未等。
````

通过时只写：

````text
01 短信验证码登录（接口流程）：通过
结果：通过 6 / 未通过 0 / 未执行 0
关键核对：验证码记录 count=1 且 60 秒失效、60 秒作废后失效、负例被拒且会话 count=0、会话 count=1 且用户进入登录态。
````

未跑通时：

````text
01 短信验证码登录（接口流程）：未跑通（环境问题）
结果：通过 0 / 未通过 0 / 未执行 6
已跑：无；未跑/阻塞：第 1-6 步，数据库连接不可用
偏差或阻塞：dbx 查询被拒，附报错原文
未覆盖：全部步骤
````

页面方式的差别只在步骤 4/5：按 `agent-browser` 技能打开登录页、填手机号与验证码、点登录，读跳转结果与页面显示，再查库确认会话落库；不做接口通道那种业务不变量展开。两轮用不同手机号；接口轮第 5 步已判业务退化，页面轮对应步骤记 `未执行`。两份报告分别标方式。

边界案例：图上的系统行为靠等触发条件，例如「验证码 60 秒未使用自行作废」，等满 60 秒再查那条记录；流程因前面的失败已停时，该行记 `未执行` 并写原因，不跳过不提。功能点没有用户端时，报告首行写 `（接口流程，无用户端）`，不硬造页面操作。
